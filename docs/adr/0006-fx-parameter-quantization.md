# FX 展开模块的参数量化归属

- 状态：已接受
- 日期：2026-10-16

## 背景

BN 等模块经过 FX 展开后，图通过 `get_attr` 直接读取 weight/bias，父模块的
forward 不会执行。此前父参数量化器虽被初始化和导出，却未参与计算；实际参数
由子 Multiply/Add 的输入激活量化器处理。给实例替换 `__call__` 无法修复这个路径，
重新包装并 detach Parameter 还会断开 QAT 主参数的梯度。

## 决策

为展开模块的参数读取插入显式 FX 调用，执行该父模块的 `param_quantizers`。
保留原始 Parameter 和 STE 梯度。通过 view/reshape 等仅改变形状的节点跟踪参数边，
关闭同一条边上消费者的输入量化器，保证参数量化只有一个归属。
激活边和 running_mean/running_var 等缓冲区继续使用原有量化路径。

校准、单独参数校准、冻结、保存重载和导出均使用相同的父参数量化器。
参数量化器设为 None 可关闭对应 QDQ。排除某层仅移除该层的参数调用；提取浮点
模型时移除全部辅助调用，qdq_weights=True 则将量化后的参数写入副本。

## 考虑过的方案

- 保留无效父量化器并仅依赖子输入量化器：参数配置和导出的参数编码仍可能脱离执行。
- 同时执行父参数和子输入 QDQ：引入不同网格的重复舍入。
- 在调用时 detach 并替换 Parameter：破坏主参数梯度和优化器身份。

## 影响与限制

此前同时保存无效父编码和子输入编码的阶段文件不能视为新图的等价 checkpoint，
应从原 FP checkpoint 重新校准。参数边上的 INT QDQ 保留；这项修复不移动 Log
或其他前端激活的量化位置，也不承诺分类精度单调提高。
