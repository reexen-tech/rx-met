# GRU carrier 共用整数目标前向

GRU 的 FP32 carrier 曾使用真实 sigmoid/tanh 和浮点比例，INT32 carrier 使用 LUT 与整数重缩放，
使 QAT 优化的函数与整数执行不同。公共 FP32 前向现在调用同一整数核心，直接复用输出、
门缓存和 mask，仅将反向所需的量化码缓存转换为 FP32，保留现有 STE 反向接口。

这一方案避免维护两份容易再次分歧的算术，但增加临时整数缓存、转换和同步成本；
FP32 缓存对绝对值超过 2^24 的整数仍不能保证精确。底层真实激活实现保留为非目标参考。
前向一致性由 8/16 位、affine/Po2 的逐缓存对照与整网整数路径验证；不声称已验证独立 NPU。
公共编码只携带标准网格，重载按所有 scale 是否为精确 2 的幂恢复执行模式，与 LSTM 一致。

锁定必须发生在待处理的编码更新完成之后。原 affine→Po2→lock 顺序会丢弃 dirty 标记，
导致导出仍是 affine scale，而运行已经切换模式。现在锁定前从已有校准统计完成推导；
不采集额外样本，QAT 期间仍保持固定编码。缺失统计时拒绝锁定不一致状态。
